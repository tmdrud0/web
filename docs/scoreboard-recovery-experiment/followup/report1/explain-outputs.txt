2) findDuplicateAppliedSequences (afterSequence = NULL, checkWindowSize = 1000)

SELECT csr1_0.scoreboard_applied_seq, COUNT(csr1_0.submission_id)
FROM contest_submission_result csr1_0
WHERE csr1_0.scoreboard_applied_seq IS NOT NULL
  AND (NULL IS NULL OR csr1_0.scoreboard_applied_seq > NULL)
GROUP BY csr1_0.scoreboard_applied_seq
HAVING COUNT(csr1_0.submission_id) > 1
ORDER BY csr1_0.scoreboard_applied_seq
LIMIT 1000;

        -> Group aggregate: count(csr1_0.submission_id), count(csr1_0.submission_id)
           (cost=41591 rows=138397)
            -> Filter: (csr1_0.scoreboard_applied_seq is not null)  (cost=27751 rows=138397)
                -> Covering index range scan on csr1_0 using idx_csr_scoreboard_applied_seq
                   over (NULL < scoreboard_applied_seq)  (cost=27751 rows=138397)

READING: no join, no filesort - a covering index scan feeding a streaming group
aggregate. This is the efficient shape: cost is proportional to the number of rows
with scoreboard_applied_seq set (all of them, once the contest is fully judged), which
is structurally required to prove no group has count > 1 - a HAVING COUNT(*) > 1 cannot
stop early on a clean range. Rows examined here scale with table size, but the per-row
cost is a covering-index compare, not a join.

SELECT csr.submission_id, s.problem_id, s.user_id, c.start_time, s.submitted_time,
       COALESCE(csr.final_result, csr.provisional_result)
FROM contest_submission_result csr
